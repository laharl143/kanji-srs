# 0010 rationale: settings and credits

Decision record for [index.md](index.md). `/develop` builds from `index.md` and can skip this file.

## Context

The tab bar already has a Settings tab, but it shows a placeholder. The first 0010 assumed a web app: server actions, a footer link on every page, and a pure `planSkip` function. On Android there are no server actions, no page footer, and the skip ahead and reset writes already exist as tested queries from spec 0002 (`raiseAssignmentsBelowLevel`, `resetProgress`).

Spec 0001 put more on this screen since then: the reminder switches and times (`user_settings` already has the columns), and credit for the bundled Noto Sans JP font. Feature 14 (review reminders) is the next slice and owns the notification package, the permission prompt, and the scheduler. The old 0010 and the built `resetProgress` disagree on what a reset wipes (notes kept, settings wiped versus notes wiped, settings kept), so one of them has to win.

The data licenses (CC BY-SA 4.0 for the EDRDG files, Creative Commons BY for the JLPT lists, SIL OFL for the font) require visible attribution. Ground rule 4 already says a new source goes into `pipeline/raw/SOURCES.json` and onto the Credits page, which today has no page to go onto.

## Options considered

The eight choices were drawn as mockups and picked on 2026-11-08. The ones with real alternatives:

### Screen layout: grouped cards (chosen) · plain Android list · progress tools on their own screen
Grouped cards match Home and the item pages and keep the danger actions apart at the bottom; the cost is the longest scroll. A plain list feels like Android's own Settings app but every change takes an extra tap into a dialog and looks unlike the rest of the app. A separate "Manage progress" screen puts reset two screens away from a stray tap, but adds a route when the typed `RESET` already guards it.

### Batch size control: stepper (chosen) · preset chips · slider
The stepper needs no package and is easy for a Maestro flow to tap; going from 3 to 20 takes 17 taps. Chips reach common sizes in one tap but cannot pick 7 or 12. A slider needs a new community package and makes an exact number fiddly.

### Time picker: Android's own dialog (chosen) · own hour and minute steppers · half hour list
`@react-native-community/datetimepicker` is in Expo's SDK list, runs in Expo Go, and follows the phone's 12 or 24 hour setting; it is one new package. Own steppers need no package but are more code and look home made. A list of 48 slots needs no package but cannot pick 8:15.

### Reminder scope: controls now, notifications in feature 14 (chosen) · all of it now · none here
Building only the controls keeps `expo-notifications` and the permission logic in the slice that tests delivery; until then the switches save but nothing fires. Building all of it now finishes Settings in one go but pulls half of feature 14 forward. Leaving the controls out makes feature 14 own a Settings section that 0001 and the scope give to this feature.

### Skip ahead picker: stepper dialog with a preview (chosen) · level list screen · typed number
The stepper fits inside the existing `ConfirmDialog` (it takes children) and shows the cost before you confirm; with many enabled levels it takes many taps. A list screen scales but adds a route and still needs a confirm. A typed number needs input checks and error text.

### Reset scope: progress and notes, keep settings (chosen) · progress only · everything
Wiping notes and keeping settings is what spec 0002 built and tested, and it is a true fresh start while your batch size and reminder times stay. Keeping notes saves your own writing but changes the built query, its test, and 0002. Wiping settings too is the same as a fresh install and loses preferences that are not progress.

### Credits link: Settings row (chosen) · info icon on every tab
A row in About is where Android users look for licenses, and 0003 already lists Credits as a pushed screen. An icon in every tab's app bar is closest to the old "link on every page" but clutters the pink bar for a page you read once.

### Credits data: typed list plus test (chosen) · generated by the pipeline
A typed list carries readable names, links, and the font and icons, which are not in the pipeline source list; a test catches a source added to `pipeline/src/sources.ts` but not credited. Generating credits into the bundle gives one source of truth, but the raw license strings read badly, the font and icons still need hand entries, and the bundle format changes.

## Rationale

Most of the hard parts already exist and are tested: the two queries that do the damage (skip and reset) came from 0002, and unlocks come from 0006. This update wires them to a screen and adds the guards around them (typed confirm, preview count, busy state, one transaction each), rather than writing new write paths. That is why the old `planSkip` goes: it would be a second, untested copy of logic that is already right.

Saving each control at once fits a phone settings screen and matches how notes save on the item page (0009). The failure path is the same toast and roll back the control to the saved value, so nothing shows a value that is not stored.

The one new package, the date time picker, is worth it because time entry is easy to get wrong by hand (12 versus 24 hour, locale), and the Android dialog is what people already know. Keeping reminder delivery out of this feature keeps the untested part (notifications only verify on an installed APK) in the slice built and checked for it.
